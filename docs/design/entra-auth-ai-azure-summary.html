Design summary · ballerinax/ai.azure

Keyless (Entra ID) auth for ai.azure

A 10-minute walkthrough. Full design, sources and proofs: docs/design/entra-auth-ai-azure.md.

Problem

  • ai.azure only sends a static api-key. Teams that disable keys or use managed identity can't use it.
  • http:Client has no token-provider hook, and a provider can't be wrapped in Ballerina. So every app ends up hand-rolling token code.
  • Python and Java users write DefaultAzureCredential().
Today's workaround (hr_agent/identity.bal, ~190 lines): fetch a managed-identity token, cache it, and run a local proxy on 127.0.0.1:8089. The proxy swaps the fake api-key for Authorization: Bearer. It works, but every agent needs its own copy.

How it looks

Ballerina
import ballerinax/ai.azure;
import ballerinax/ai.azure.identity;

// Keyless, default chain: Azure CLI on a laptop, managed / workload identity when deployed
final azure:OpenAiModelProvider m1 = check new (url, {'type: "default"}, "gpt-5.5");

// Explicit user-assigned managed identity
final azure:OpenAiModelProvider m2 = check new (url, {'type: "managedIdentity", clientId: miClientId}, "gpt-5.5");

// API key still works, unchanged
final azure:OpenAiModelProvider m3 = check new (url, apiKey, "gpt-5.5");

// Or one configurable for both: key or keyless, chosen per environment
configurable string|identity:CredentialConfig modelAuth = {'type: "default"};

Rules (same as Microsoft's DefaultAzureCredential):

  • Not available (e.g. env vars missing) → try the next one.
  • Available but fails (e.g. wrong secret) → stop with that error. Don't silently fall through.
  • Once one works, remember it for later calls.

Examples: on your laptop → Azure CLI. In a Foundry hosted agent → managed identity. On AKS → workload identity. On an on-prem server with the 3 env vars → service principal.

Key decisions

DecisionChoiceWhy
Where the code livesSubmodule ai.azure.identity inside ai.azure, extract-readyFastest to ship; same pattern as azure.storage.blob; no new package to own. Ballerina-only public types, so it can be moved later.
Token engineJava azure-identity, the same jar set azure.storage.blob ships, with TLS/proxy wired inMicrosoft-maintained protocols and full DefaultAzureCredential behaviour. Local proofs pass: SSL_CERT_FILE trust works only when wired, and it coexists cleanly with ballerina/http.
Attaching the tokenAuthorization: Bearer per request on plain HTTP clientsWorks today; ballerina/http has no token-provider hook, and the generated connectors only take static tokens
API shapeWiden the existing apiKey param: string|CredentialConfig|TokenCredentialNon-breaking (minor release); Integrator generates positional code
Config formatRecords with a required type fieldConfig.toml picks the first matching union member, so without type {} becomes the wrong credential
Token scopeDerived from the URL, overridableProject endpoint accepts only ai.azure.com (tested); Search uses search.azure.com

Credential sources

Phase 1

  • Default chain (env → workload identity → managed identity → Azure CLI)
  • Managed identity: App Service style (Foundry hosted agents, Container Apps) and IMDS (VMs, AKS)
  • Workload identity (AKS) · service principal with secret · Azure CLI · static token · your own TokenCredential

Phase 2

  • Client certificate (slot reserved now, non-breaking)
